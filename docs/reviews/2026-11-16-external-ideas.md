## 1. 取り入れる候補（確かめたもの）

### 1-1. 無料の公開 API で、欠けたデータを埋められる

[Boatrace Open API](https://github.com/boatraceopenapi/api)（非公式・GitHub Pages の静的な JSON・認証なし・1 日 1 ファイル）が、全 24 場の番組表・直前情報・結果・全券種の払戻を配っている。

| 確かめたこと（11/16） | 結果 |
|---|---|
| 配信の範囲 | 2024-06-01・2025-01-01・2025-11-21・2025-12-01・2026-01-15・04-01・05-19・06-10 の日付が取れた（README の「2026 年以降」より前もある。いちばん古い日は未確認） |
| 手元の公式の記録との突き合わせ | 2025-12-01・2026-04-01・2026-06-10 の 3 日・384 レースのうち、比べられた 380 レースで 3連単の着順と払戻が全部一致（残り 4 レースは手元に結果が無い） |
| 手元で欠けているもの | 2026-04-01 と 2025-12-01 は番組表が 0 件、2026-06-10 は払戻が 0 行。API にはどちらもある |
| 中身 | 番組表は級別・全国と当地の勝率・モーターとボートの 2 連率まで。払戻は拡連複 3 行・単勝・複勝を含む |

埋められる見込みのもの:

- 番組表の約半年（2025-11-21〜2026-05-19。知識ベース R4）。
- K ファイルが手元に無い日の結果と払戻（2026-05-21〜25、6/2〜7/3）。
- 過去の払戻表の不備（拡連複が 1 行だけ・単勝と複勝が無い。R1）。

**結果（11/16 夜）: API は使わず、公式アーカイブから取り直した。** 調べ直すと、欠けた日のファイルは公式アーカイブに全部あり（番組表 b251201・b260301・b260510、結果 k260605・k260523 で確認）、取り直しは 10月の監査（data-audit の D1・D4）で提案済みのまま実行されていなかった。公式のほうが確実で、新しい取得元も増えないので、そちらを使った。

- 番組表: 180 ファイル・27,864 レース（2025-11-21〜2026-05-19）。22:24〜22:56、失敗 0。
- 結果と全券種の払戻: 37 ファイル（2026-05-21〜25・06-02〜07-03）。5,673 レース・払戻 56,718 行、失敗 0。
- 毎晩・毎朝のジョブに同じ処理を入れたので、以後の欠けは自動で埋まる（`daily-results.sh`・`daily-programs.sh`。夜間だけ・1.5 秒間隔・1回 200 ファイルまで）。
- Boatrace Open API は、照合の予備として覚えておく（3 日・380 レースで公式の記録と一致）。取り込みは作っていない。
- 残り: 過去の払戻表の不備（拡連複 1 行・単勝と複勝なし。2004〜2026-06-01）。

### 1-2. 締切 10 分前（T-10）の取得で選んだ本命は、確率が高めに出ている兆しがある

| 取得 | 確率 22% 以上の本命 | 的中 | 見込み | 的中 ÷ 見込み |
|---|---:|---:|---:|---:|
| T-5 | 321 件 | 25.5% | 25.9% | 0.98 |
| T-10（全期間 7/1〜10/28） | 295 件 | 22.4% | 26.9% | 0.83（約 1.7 標準誤差） |
| T-10（前半 7〜8月） | 180 件 | 23.9% | 27.0% | 0.89 |
| T-10（後半 9〜10月） | 115 件 | 20.0% | 26.8% | 0.75 |

- 補正の温度と直前の動きの重みを T-10 用に選び直しても、最良はいまと同じ（T=0.9・β=0.25）。全体の補正では直らない。
- 前半で決めた割引（0.89 倍）を後半の再生（1日 2 件まで）に当てはめても、的中 ÷ 見込みは 0.98 → 0.99、件数は 95 → 92 で、良くなったとは言えない。
- **決まりは変えない。** 事前登録どおり、精算 50 件で的中 ÷ 見込みを見る（[favorite-buy-preregistration](2026-11-16-favorite-buy-preregistration.md) の 4 章）。そのとき 0.8 を下回っていたら、T-10 の割引を 4 代目として提案する。
- T-5 だけで判定する案は取らない。T-5 の最初の取得が締切 7 分以上前だったのは 55.5%（10/16〜10/28 の 780 レース）で、通知が間に合わないレースが 4 割を超える。

## 3. 他の人が同じ失敗をしていた（知識ベースの裏づけ）

[funayomi-ai](https://github.com/sakiyomiman/funayomi-ai)（負けた検証も公開している予想エンジン）の README より:

- 期待値だけで買い目を選ぶと、万券ばかり買って回収率 0% だった → boat-pon の K13（v3 の BUY は全部 1-2-3 の平均 64 倍）と同じ形。
- 数日分に合わせ込むと、別の日で 104% → 68% に崩れた → 手法の罠 3（条件を細かく分けるほど見かけは上がる）。
- 「見送りも予想」「負けも公開」→ boat-pon の「記録は行動できた時点で数える」「不合格も書く」と同じ方針。

## 4. 見たが、取り入れないもの

| 案 | 出どころ | 取り入れない理由 |
|---|---|---|
| ニューラルネット・XGBoost などの寄せ集めと強化学習 | boat-race-predictor | 成績の数字が示されていない。公開情報のモデルは市場に負ける（K1・K3） |

| 2連複の本命に替える | フネヨミ・K14（2連複の上位 3 点は的中 67%・回収率 80%） | 2連複のオッズを取っていない（新しい取得）。券種間の値付けはそろっている（K11）ので回収率は変わらず、当たりやすさだけが上がる。3 代目の判定（精算 180 件）のあとに考える |
| 無料 API を通知の代わりの入口にする | Boatrace Open API | オッズが無い。更新は 10〜20 分遅れ。締切前の判定には使えない |
