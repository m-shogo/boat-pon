# ノートPCが眠っていても動かす構成の下調べ（2026-11-16・課題 #12）

ユーザーの問い（11/16）: 毎日の作業は自動にしてほしい。PC の電源をつけているかは微妙。
**決定（2026-11-16、ユーザー）: お金はかけない。** VPS（D）と機械の購入（C）は選ばない。残るのは、いまの Mac で動かすこと（6 章）。ここには、測った事実と候補の比較を残す。

## 3. 公式サイトの決まり

- サイトポリシーに、自動のアクセスを名指しで禁じる・認める条項は無い。
- 禁止事項に「大量のアクセスなど、本サイトの運営に支障を与える行為」がある。「大量」の基準は書かれていない。
- 文書・画像などは、私的な使用の範囲を超えて無断で複製・頒布できない。
- 移しても取得の回数は変えない。**Mac と移し先を同時に動かさない**（回数が倍になる。LINE も二重に届く）。取ったデータは公開しない。

## 4. おすすめと、進めるなら最初の一歩

おすすめは D（国内の VPS・2GB）。理由は、初期費用が無く、2 週間のお試しで「届くか・動くか」を確かめてからやめられること。C は確実だが、最初に 3〜5 万円かかり、置き場所と保守が要る。

ただし、月 約 1,700 円を払う価値があるかは、ユーザーが決めること。この仕組みは paper の検証で、利益の見込みは無い（知識ベース K1・K17）。払って得られるのは「通知が毎日届くこと」と「本命予想の判定（精算 180 件）が欠けで延びないこと」。

進める場合の順番（いちばん安い確認から）:

1. お試しの VPS から、公式サイトのオッズのページを 1 回だけ取れるか確かめる。取れなければ D はやめて C か A。
2. Linux で動くように直す（`date -v`・定期実行・パス）。Mac でも動くままにする。
3. DB と公式ファイルを移し、LINE を送らない設定で 2〜3 日並べて動かす。この間、VPS 側は公式サイトに取りに行かず、Mac の記録と判定が同じになるかだけを見る。
4. 切り替える: Mac の定期ジョブを止め（`launchctl bootout`。ユーザー作業）、VPS 側を有効にする。Mac は開発と分析に使い、DB は夜に VPS から持ってくる。

人がすること: VPS の申し込みと支払い、SSH の鍵の登録、Mac の定期ジョブの停止。

## 6. お金をかけない場合（決定後の整理）

眠った理由（`pmset -g log`、11/15〜11/16）: きっかけは蓋を閉じたこと（Clamshell Sleep 4 回）。そのあとは、短く起きてはまた眠る動きの繰り返し（124 回）で、定期ジョブはその合間にしか動かない。電源につないで蓋を開けている間は眠っていない。

| できること | 誰が | 効き目と注意 |
|---|---|---|
| 机に置いている間は、蓋を開けて電源につなぐ | ユーザー | いまの設定のままで眠らない。忘れた日は欠ける |
| 蓋を閉じても眠らない設定にする（この Mac には `SleepDisabled` の項目があり、いまは 0） | ユーザー（管理者のパスワードが要るシステムの設定。エージェントは変えない） | 蓋を閉じたままでも動く。**閉じたままカバンに入れると熱がこもる。電源につないでいないとバッテリーが減り続ける。** 公式の手引き（`man pmset`）に載っていない設定なので、勧めはしない |
| 家にある使っていない PC・古い Mac を常時起動にする | ユーザー（あれば） | 買わずに C と同じ効果。Linux や古い macOS で動くように直す作業は要る |
| 眠っても壊れないようにする | 済み（自動） | 結果と払戻は後から自動で埋まる（`daily-results.sh`）。欠けた量は毎晩の日次まとめに出る。締切前のオッズと、その時間の BUY の通知だけは戻らない |

欠けがあっても、本命予想の判定（精算 180 件）は偏らない。届く件数が減って、判定までの期間が延びるだけである。

## 7. 家にある古い MacBook Pro を使う案（11/16 夕方、ユーザーの回答を受けて）

ユーザーの回答: 家に 2015〜2017 年ごろの MacBook Pro がある。電源につなぎっぱなしでないと落ちる（バッテリーが弱っている）。家の Wi-Fi と電源につないだまま置くことは「たぶんできる」。

- **電源につなぎっぱなしでないと落ちる点は、常時起動の用途では問題にならない。** 置きっぱなしの機械は、もともとつなぎっぱなしで使う。困るのは停電やコードが抜けたときだけで、起動し直せば再開する（結果と払戻は自動で埋まる）。
- **膨らみに注意**: 弱ったバッテリーをつなぎっぱなしにすると、膨らむことがある。底やトラックパッドが盛り上がってきたら使うのをやめる。
- **動く Node の版（公式の BUILDING.md で確認）**:

| 機種の年 | 入る macOS（機械で要確認） | Node 24（macOS 13.5 以上） | Node 22（macOS 11.0 以上） |
|---|---|---|---|
| 2017 | 13（Ventura）まで | 13.5 以上に上げれば動く | 動く |
| 2015・2016 | 12（Monterey）まで | 動かない | 動く |

- この repo は Node 24 を指定している（`.nvmrc`・`engines`）。Node 22 でも動くかは未確認。`node:sqlite` は 22.5.0 で入り、22.13.0 からフラグなしで使える（公式の文書）。確かめるには、いまの Mac に Node 22.23.5（公式の配布ファイル 50.0MB）を入れてテストを回す。
- macOS のままなので、launchd・シェルの日付計算はそのまま使える。Linux への移植は要らない。
- 進め方（いちばん安い確認から）:
  1. いまの Mac で、Node 22 でテスト 265 件が通るかを見る。通らなければ、直す量を見て決める。
  2. 古い Mac の macOS の版・メモリ・空き容量を見る。公式サイトのページを 1 回取れるか確かめる。
  3. repo・DB（15.8GB）・公式ファイル・LINE の設定を移し、LINE を送らず公式サイトにも取りに行かない設定で、判定がいまの Mac と同じになるかを見る。
  4. 切り替える。通知と収集をする機械は 1 台だけにする（いまの Mac 側は、コードの切り替えで収集と通知を止める。launchd の操作に頼らない）。いまの Mac は開発と分析に使い、DB は夜に古い Mac から持ってくる。
- 人がすること（古い Mac の前で 1 回だけ）: 電源と Wi-Fi につないで起動する・macOS の版を見る・「共有」の「リモートログイン」をオンにする（システムの設定）・いまの Mac から鍵を 1 回登録する（パスワードを打つのは本人）。それ以降の設定は、いまの Mac から遠隔で行う見込み（launchd の登録だけは、本人の 1 コマンドが要るかもしれない）。
