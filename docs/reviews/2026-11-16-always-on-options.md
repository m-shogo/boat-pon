# ノートPCが眠っていても動かす構成の下調べ（2026-11-16・課題 #12）

ユーザーの問い（11/16）: 毎日の作業は自動にしてほしい。PC の電源をつけているかは微妙。
結論は出していない（契約・購入・システム設定はユーザーが決める）。ここには、測った事実と候補の比較を残す。

## 1. いまの事実（11/16 に実測）

| 項目 | 値 |
|---|---|
| 実行している機械 | MacBook Pro（M5 Pro・24GB・macOS 26.4.1）。launchd が本番の作業コピーを直接実行 |
| 眠る条件 | 電源につないで蓋を開けていれば眠らない（AC は sleep 0、`caffeinate -s`）。蓋を閉じたとき・バッテリーのとき（1 分）に眠る |
| 欠け | 11/3〜11/16 の 14 日で、判定を記録できたのは番組の 37%〜95%。半分に届かない日が 4 日 |
| 取り直せないもの | 締切前のオッズ（眠っている間の分は戻らない）。BUY の通知も出ない。結果と払戻は後から埋まる |
| 資源 | auto-odds の 1 回の実行でメモリは最大 約 500MB、19〜85 秒。DB は 15.8GB（年 約 6GB 増）。ライブ経路が読む公式ファイルは 約 1.7GB |
| 公式サイトへのアクセス | オッズの取得は 1 日 405〜434 回（11/10・11/11）。並列は 2 |
| Mac 専用の箇所 | シェルの `date -v`（4 本）、launchd の登録ファイル 11 個、Homebrew と mise のパス、Google Drive への複製先のフォルダ |

## 2. 候補の比較

| 候補 | 費用（調べた時点） | 良い点 | 悪い点・未確認 |
|---|---|---|---|
| A. いまのまま（蓋を開けて電源につなぐ） | 0 円 | 何も変えない | 人の注意に頼る。欠けが続く |
| B. Mac を蓋を閉じても動かす | 0 円〜（外付けディスプレイがあれば） | 移す作業が無い | Apple の案内する方法は「電源＋外付けディスプレイ＋外付けキーボードとマウス」。持ち出すと止まる。蓋を閉じても眠らせない設定は `man pmset` に載っておらず、管理者権限が要る（ユーザー作業） |

メモリは 1 回の実行で約 500MB を使い、速報や直前情報の取得と重なるので、VPS なら 1GB ではなく 2GB にする。

## 3. 公式サイトの決まり

- サイトポリシーに、自動のアクセスを名指しで禁じる・認める条項は無い。
- 禁止事項に「大量のアクセスなど、本サイトの運営に支障を与える行為」がある。「大量」の基準は書かれていない。
- 文書・画像などは、私的な使用の範囲を超えて無断で複製・頒布できない。
- 移しても取得の回数は変えない。**Mac と移し先を同時に動かさない**（回数が倍になる。LINE も二重に届く）。取ったデータは公開しない。

## 4. おすすめと、進めるなら最初の一歩

おすすめは D（国内の VPS・2GB）。理由は、初期費用が無く、2 週間のお試しで「届くか・動くか」を確かめてからやめられること。C は確実だが、最初に 3〜5 万円かかり、置き場所と保守が要る。

ただし、月 約 1,700 円を払う価値があるかは、ユーザーが決めること。この仕組みは paper の検証で、利益の見込みは無い（知識ベース K1・K17）。払って得られるのは「通知が毎日届くこと」と「本命予想の判定（精算 180 件）が欠けで延びないこと」。

進める場合の順番（いちばん安い確認から）:

1. お試しの VPS から、公式サイトのオッズのページを 1 回だけ取れるか確かめる。取れなければ D はやめて C か A。
2. Linux で動くように直す（`date -v`・定期実行・パス）。Mac でも動くままにする。
3. DB と公式ファイルを移し、LINE を送らない設定で 2〜3 日並べて動かす。この間、VPS 側は公式サイトに取りに行かず、Mac の記録と判定が同じになるかだけを見る。
4. 切り替える: Mac の定期ジョブを止め（`launchctl bootout`。ユーザー作業）、VPS 側を有効にする。Mac は開発と分析に使い、DB は夜に VPS から持ってくる。

人がすること: VPS の申し込みと支払い、SSH の鍵の登録、Mac の定期ジョブの停止。
