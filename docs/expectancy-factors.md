# 期待値に影響する競技環境メモ

最終更新: 2026-05-23

Boat Pon は「過去データをそのまま全部混ぜる」のではなく、競技環境が変わった時期を分けて検証する。

## 重要度S: プロペラ制度

### 持ちペラ時代

- 期間: 1988年5月〜2012年3月末目安
- 選手が自分のプロペラを持ち込み、調整して使用できた。
- 公開データに出にくい「ペラ技術」「ペラグループ」「伸び足の作り方」が効きやすい。
- モーター2率/勝率が、そのまま機力を表しにくい可能性がある。

### 新プロペラ移行期

- 期間: 2012年4月
- 日本モーターボート競走会の沿革では、浜名湖が2012-04-12から先行実施、その他は2012-04-27以降を初日とする開催から実施。
- この月は場ごとに移行タイミングが混ざるため、モデル上は移行期として分ける。

### 貸出ペラ時代

- 期間: 2012年5月〜現在
- モーター1基につきプロペラ2枚を配備し、モーターとセットで貸し出す制度。
- モーター/ボート2率、展示、選手勝率など、公開データの説明力が持ちペラ時代より上がった可能性がある。

Boat Pon の取り扱い:

- 現代レースの候補生成では、原則として2012-05-01以降の結果を学習に使う。
- 2012-04-01〜2012-04-30は移行期として、現代モデルからは外す。
- 2004〜2012-03の結果は、歴史分析や比較には使うが、現代BUY判定の主学習には混ぜない。

参考:

- 日本モーターボート競走会 沿革: https://www.mbkyosokai.jp/history.html
- マイナビニュース「選手持ちプロペラ制度廃止へ。新プロペラ制度がスタート」: https://news.mynavi.jp/article/20120329-a030/
- BOAT RACE公式 プレイバック: https://www.boatrace.jp/owsp/sp/extra/race/01_20160823/monthly/playback.html
- マクール 2012年回顧: https://sp.macour.jp/columns/macour_timemachine/176266/

## 重要度A: 2011年3月の東日本大震災

- 2011-03-13〜31は全場開催見送り期間として扱う。
- K/B LZHの有無と中止情報は docs/missing-dates.md に整理済み。
- 学習期間の連続性や月別ROIを読むとき、2011年3月は通常月として比較しない。

## 重要度A: グレード競走・番組体系の変更

- 2013年にSG/GI/GII/GIII開催要綱の一部改正があり、グランプリの開催期間拡大、ヤングダービー新設、レディースチャレンジカップ新設などがある。
- 一般戦だけを見るモデルと、SG/GIを含むモデルは分ける余地がある。
- 現時点のBoat Ponはレースグレード抽出が薄いため、番組表raw_jsonから競走名/グレード推定を追加すると効く可能性がある。

参考:

- 日本モーターボート競走会 沿革: https://www.mbkyosokai.jp/history.html

## 重要度A: 気象・水面・安定板・周回短縮

- 強風・高波時は安定板装着や周回短縮が入り、通常の会場/コース傾向と別物になりやすい。
- 荒天中止日は通常結果として学習しない。
- 天候、風速、波高、安定板、周回短縮が取れるようになったら、まずはBUY降格条件として使う。

## 重要度B: 進入固定・企画番組

- 進入固定は枠なり前提が強く、通常レースより進入の不確実性が低い。
- 企画番組、女子戦、ルーキー戦、匠シリーズなどは母集団を分けた方がよい。
- 番組表の競走名からカテゴリ推定を作る余地がある。

## 重要度B: 締切・発売環境・スマホ普及

- 2012年4月に場間場外発売・電話投票の締切時間が3分前から2分前へ短縮。
- 2012年6月にスマートフォン版BOAT RACE公式Webサイトがオープン。
- オッズ形成や締切直前の票の入り方が変わった可能性があるため、古いオッズデータと現代オッズデータは分けて検証する。

参考:

- 日本モーターボート競走会 沿革: https://www.mbkyosokai.jp/history.html

## 実装済み

- `src/domain/raceRegime.ts`
  - 日付から持ちペラ時代/移行期/貸出ペラ時代を判定。
  - 現代予測では2012-05-01以降の結果のみを比較可能データとして使う。
- `server/candidates.ts`
  - 候補生成時に対象日のレジームに合う結果だけでモデルを作る。
- `src/domain/walkForward.ts`
  - ウォークフォワード検証でも対象日のレジームに合う過去結果だけを学習に使う。

## 次に取り入れる候補

1. 番組表raw_jsonから競走名カテゴリを抽出し、SG/GI/一般/女子/ルーキー/匠を分ける。
2. 非公式サイトや公式ページから過去オッズを候補レースだけ低頻度・キャッシュ前提で補完する。
3. 気象・風速・波高・安定板・周回短縮を取得できる範囲で追加する。
4. 年代差分を固定境界だけでなく、ローリング3年/5年で監視する。
